## Инцидент №1: Ошибка 500 при обновлении остатков FBS (WB Партнёры)

### 1. Поиск и выгрузка логов в терминале
Для поиска причины сбоя в файле `seller_stocks.log` за время инцидента (`2026-11-15 14:30:00`) использована фильтрация по времени и уровню ошибки с захватом контекста (3 строки до и после сбоя):

```bash
grep -C 3 "2026-11-15T14:30" seller_stocks.log | grep -C 3 "ERROR" > wb_stocks_error.txt
```

### 2. Баг-репорт (BUG-LOG-01)
* **Заголовок:** Ошибка `500 Internal Server Error` при обновлении остатков по модели FBS через API `PUT /api/v3/stocks/warehouse_12`
* **Серьёзность (Severity):** Critical
* **Приоритет (Priority):** High
* **Окружение:** Сервер B2B-портала WB Партнёры, путь к логам: `/var/www/seller/logs/seller_stocks.log`, время инцидента: `2026-11-15 14:30:00`.
* **Шаги воспроизведения:**
  1. Открыть Postman (или терминал).
  2. Отправить `PUT`-запрос на эндпоинт `/api/v3/stocks/warehouse_12` с валидным телом запроса (баркод товара и новое количество остатка).
  3. Проверить статус-код ответа сервера.
* **Ожидаемый результат:** Остатки на складе успешно обновляются, сервер возвращает статус-код `200 OK` (или `204 No Content`).
* **Фактический результат:** Остатки не обновляются, сервер возвращает ошибку `500 Internal Server Error`.
* **Доказательства (фрагмент лога):**
```text
2026-11-15T14:30:01.112Z [INFO] Incoming PUT /api/v3/stocks/warehouse_12
2026-11-15T14:30:01.145Z [ERROR] NullPointerException: Failed to update stock balance for warehouse_12
2026-11-15T14:30:01.148Z [INFO] Response status: 500
```

## Инцидент №2: Ошибка 404 при запросе карточки товара (Витрина Wildberries)

### 1. Поиск логов по `trace_id` и проверка базы данных
Для расследования сбоя при открытии карточки товара с артикулом `nm_id=8845120` выполнены поиск в логах по уникальному идентификатору трассировки и прямой запрос в БД:

```bash
grep -C 3 "wb-trc-77419" catalog.log > wb_catalog_error.txt
```

```sql
SELECT * FROM wb_products WHERE nm_id = 8845120;
```

### 2. Баг-репорт (BUG-LOG-02)
* **Заголовок:** Ошибка `404 Not Found` при открытии карточки товара (`nm_id=8845120`) через `GET /api/v1/catalog/product/8845120` из-за отсутствия записи в БД
* **Серьёзность (Severity):** Major
* **Приоритет (Priority):** Medium
* **Окружение:** Сервер витрины Wildberries, путь к логам: `/var/www/catalog/logs/catalog.log`, БД: PostgreSQL (`wb_products`).
* **Шаги воспроизведения:**
  1. Открыть Postman (или браузер).
  2. Отправить `GET`-запрос на эндпоинт `/api/v1/catalog/product/8845120` для получения данных карточки товара.
  3. Проверить статус-код и тело ответа сервера.
* **Ожидаемый результат:** Сервер находит карточку товара в базе данных, отдаёт её данные и возвращает статус-код `200 OK`.
* **Фактический результат:** Карточка товара не открывается, сервер возвращает ошибку `404 Not Found` с сообщением `"Product card not found in database"` (`trace_id: wb-trc-77419`).
* **Доказательства (лог + результат SQL-запроса):**
```text
Фрагмент лога:
2026-11-15T16:12:04.501Z [WARN] [trace_id=wb-trc-77419] Product card not found in database, nm_id=8845120

Результат SQL-запроса (SELECT * FROM wb_products WHERE nm_id = 8845120):
0 rows returned (запись в таблице wb_products отсутствует).

Вывод: Ошибка 404 Not Found возникает из-за отсутствия записи о товаре с артикулом nm_id = 8845120 в базе данных (карточка удалена или не прошла синхронизацию с порталом продавца).
```
