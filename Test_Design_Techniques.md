# Применение техник тест-дизайна: Классы эквивалентности и Граничные значения

**Объект тестирования:** Поле ввода «Количество единиц товара» в корзине интернет-магазина (E-commerce).  
**Требования к полю:**
- Поле принимает только целые положительные числа.
- Минимальное количество товара для заказа — **1 шт.**
- Максимальное количество товара в одном заказе — **99 шт.**
- При вводе невалидных данных система должна блокировать оформление заказа и выводить информационное сообщение об ошибке (либо автоматически корректировать значение до ближайшего допустимого).

---

## 1. Разбиение на классы эквивалентности (Equivalence Partitioning)

Чтобы не проверять все возможные числа вручную, разделим все входные данные на 3 основных класса:

| Класс эквивалентности | Диапазон значений | Тип класса | Тестовое значение | Ожидаемый результат |
| :--- | :--- | :--- | :--- | :--- |
| **КЭ-1:** Числа меньше минимума | `≤ 0` (включая отрицательные) | Невалидный | `-5` | Ошибка валидации / ввод заблокирован |
| **КЭ-2:** Допустимый диапазон | `1 – 99` | Валидный | `25` | Значение принято, сумма корзины пересчитана |
| **КЭ-3:** Числа больше максимума | `≥ 100` | Невалидный | `150` | Сообщение «Максимум 99 шт.» / автозамена на `99` |
| **КЭ-4:** Нечисловые символы | Буквы, спецсимволы, пробел | Невалидный | `abc`, `@#`, ` ` | Ввод символов запрещён или ошибка формата |
| **КЭ-5:** Дробные числа | Числа с точкой/запятой | Невалидный | `2.5`, `1,5` | Ввод разделителя заблокирован / ошибка |

---

## 2. Анализ граничных значений (Boundary Value Analysis)

Ошибки в коде чаще всего возникают на стыке границ (`<` вместо `<=`), поэтому проверяем саму границу и соседние значения (`-1` и `+1` от границы):

| ID | Проверяемая граница | Вводимое значение | Тип проверки | Ожидаемый результат |
| :--- | :--- | :--- | :--- | :--- |
| **BV-01** | Нижняя граница `- 1` | `0` | Негативная | Заказ не оформляется; кнопка «-» неактивна или товар удаляется после подтверждения |
| **BV-02** | Нижняя граница | `1` | Позитивная | Значение `1` принято, расчёт стоимости корректен |
| **BV-03** | Нижняя граница `+ 1` | `2` | Позитивная | Значение `2` принято, сумма удвоена |
| **BV-04** | Верхняя граница `- 1` | `98` | Позитивная | Значение `98` принято без предупреждений |
| **BV-05** | Верхняя граница | `99` | Позитивная | Значение `99` принято, кнопка «+» становится неактивной |
| **BV-06** | Верхняя граница `+ 1` | `100` | Негативная | Система ограничивает ввод на `99` или выводит предупреждение о лимите |

## Вывод
Применение **классов эквивалентности** и **анализа граничных значений** позволило сократить количество проверок со 100+ случайных вариантов до **11 целевых тест-кейсов**, полностью покрывающих как позитивные сценарии, так и критические границы.
